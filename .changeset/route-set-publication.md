Route-set changes reach every dev server. Start on Rsbuild now reloads the open tab when the client's route tree changes (a route added, deleted or renamed, a page turned into a server handler or back, a lazy file added), once the client and the server both serve it, and only once: in an app that installed Start the tab is no longer reloaded by Rsbuild's client at the client's compile on top of it, with an `HMR update failed` line in the console; with RSC the reload goes over the RSC client's channel, and nothing reloads when the app sets `dev.liveReload: false`. On Vite dev, the modules of the files a generator run replaced are invalidated when the run is published, so a route tree whose watcher event Vite dropped or another plugin held is not served stale. The client's route tree orders each sibling list after leaving out server-only routes, so a pathless layout whose only route below it is server-only no longer takes `/` from the index route, and it is found under its real path when `generatedRouteTree` is in a linked directory. A generator replaced by a `tsr.config.json` change no longer overwrites its successor's route tree, a cold generation failure followed by another reports the second, a generator session closed before its watcher is ready ends its `watch()`, and a Start `vite build --watch` whose client watcher closes during its first build ends. The generator exports `contentDigest` and `ownersLast`, and answers `sourceDigest`, `treeDigest` and `retire()`.
