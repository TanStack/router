'@tanstack/router-plugin': minor
---

Route code splitting and route HMR run on the new compiler core instead of Babel: faster dev startup, HMR and builds, with the same production output shape.

**What changes for your app when you upgrade:**

- **Routes the compiler cannot read statically stay unsplit with one warning per file per build** naming the file: route options built by a helper call (`createFileRoute('/x')(makeOptions())`), imported from another module or written to after their declaration, and methods that read `this`. Main split some of these silently or crashed. What a spread or a computed key holds isn't split either (the options written next to it still are); it warns only with `codeSplittingOptions.deleteNodes` set.
- **With `deleteNodes` set (as in every TanStack Start client build), options the compiler can't read build and warn**, naming the file: a listed option they hold isn't removed, so the code it reads stays in the output. A listed option written next to a spread is still removed.
- **`codeSplittingOptions.deleteNodes` applies with `autoCodeSplitting: false` too**: the listed options are removed from the route files in dev and builds. Before, only the code splitter read `deleteNodes`, so it did nothing without `autoCodeSplitting`.
- **A route module that does not parse fails a build** naming the file; a dev server warns and leaves the module as it is.
- **`routeTree.gen.ts` formatting changes** (`enableRouteTreeFormatting` now defaults to `false`): once if your formatter ignores the file, as the installation guides recommend; see the route generator's changeset otherwise.

- Any route option value splits: identifiers, inline functions, method shorthands (#8623), object-form loaders (#8753), casts, `satisfies`, calls such as `memo(Page)`, and options held in a module-level constant. Module state the route module and its chunks share exists once (#8754, #8505), and a split chunk reads the binding itself, never the value `export default x` took (of a reassigned `let`, or above its `var`). A component exported under a string name (`export { Page as 'page-view' }`) next to a split component builds (main failed).
- **Exported route components and helpers are split too.** An exported function, class, value or component only split code needs leaves the route module: in a build it moves to a small side-effect-free module of its own that the route module re-exports (one instance for every other module importing it from the route file; the bundler drops it when nobody does), and each split chunk carries its own copy when the copy is functions and primitive constants nothing writes and nothing compares or constructs, so the chunk never depends on where the bundler places that module (Rolldown < 1.1.5 and a `manualChunks` group merging into the entry kept it eager). In dev the binding stays in the route module and the chunk copies it the same way. An importer of the route file and the route's chunk therefore hold two instances of such a function (as on main); a class, an object, a call result and other values with an identity, state, effects and augmented bindings (`Page.displayName = …`) are never copied: the chunk imports the one instance from that module. That module is a destination like a split chunk: an export with side effects of its own (`export const store = createStore()`) leaves with them, and a top-level statement using only that export (`register(store)`) goes with it; the module runs when something uses the export, and the bundler drops it, statement included, when nothing does. An export that some output renders differently (a server function's handler held by its provider) stays. Exported bindings that must stay in the route module (reassignment, read by the route module itself) and extracted modules an entry chunk loads anyway (another module imports the binding through the route file, or the bundler's chunk configuration merges a module the chunk imports into the entry) are each reported once per file, in dev and in builds, on every bundler.
- **A top-level declaration only split code needs that must stay in the route module is reported** once per declaration, in dev and in builds, on every bundler, positioned at it and naming what keeps it: a top-level change of it, or a value it reads as the file loads. Code several split options read, effects included, goes to one lazy shared module they import, evaluated once when the first of them loads. Calls of the router's own side-effect-free APIs with constant arguments (`getRouteApi`, `linkOptions`, `createLink`, `createRouteMask`, `lazyRouteComponent`, `lazyFn`, `retainSearchParams`, `stripSearchParams`, `parseSearchWith`, `stringifySearchWith`, `createRouterConfig`) are no such side effect when imported from the router package (also under another name or as a namespace member): `const { useSearch } = getRouteApi('/x')` splits with the component.
- **Options removed by `codeSplittingOptions.deleteNodes`** (in every TanStack Start client build: `server`, `ssr`, `headers`) take what only they read out of every output of the route file, split chunks and extracted modules included: a default value in a destructuring declaration that a split component also reads (`const { title, secret = readSecret() } = …`, `secret` read only by a server handler) no longer brings its server-only import into a client chunk, nor does it next to a rest element (`const { secret = readSecret(), ...rest } = …` keeps `secret` without its default, so the key stays out of `rest`); main kept them in the route's shared chunk.
- `createFileRoute` & co. are recognised by their import binding. Routes whose options cannot be read statically, and methods or function expressions that read `this` (#8688), stay in the route module with one warning naming the file.
- Route HMR keeps split components' lazy wrappers across updates in React, Solid and Vue and refreshes edits of split loaders and other non-component options on Rspack and webpack.
- Production output is decided by the bundler's mode and is identical with `addHmr: false`.
- Rspack and webpack use the plugin's own loader: project paths with `'`, `#` or spaces work (#7754). Rspack/webpack no longer rebuild every environment once after the first watch build.
- Removed: the `@babel/*` dependencies and the direct `chokidar` dependency (the route generator's watcher brings it). `@babel/core` no longer comes with the plugin: if your app runs Babel itself (for example for the React Compiler), declare `@babel/core` in your own `devDependencies`. New entry `@tanstack/router-plugin/planners` exposes the route planners to TanStack Start.
