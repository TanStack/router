Experimental: Generate route modules. A package that declares `tanstack.router.module` in its `package.json` gets qualified route ids (`<package>:<path>`), a generated route scope (`routeScope.gen.ts`, with one namespace file per included or used module), a public contract (`routeContract.gen.ts`, exported as `./route-types` after the package's own declaration build), a runtime entry (`routeModule.gen.ts`, exported as `./route-module`) and a topology manifest (`.tanstack/route-module.json`) for includers. Module identity is the package name. Applications and modules mount modules with the `routeModules` option: `includes` chooses the host route and mount path of each module and `uses` references modules mounted elsewhere. An application installs a module several times by including it once per installation, each named with `as`; every installation gets its own namespace and route ids, and a module that uses it links to the installation mounted above it. A module mounted under path params gets a namespace typed with them in its includers; the generator rejects a module that uses it without being mounted below those params, and rejects mounts whose full paths collide. `tsr generate` emits the module files. Packages emit and check declarations with their own TypeScript projects; Nx or similar workspace tooling reruns generation and compilation in dependency order when sources, configuration or provider artifacts change. `tsr watch` retains its standalone route-directory and configuration watching. The bundler plugin compiles, code-splits and hot-updates mounted module routes, including every installation of a module installed several times. Applications without route modules generate the same output as before.
