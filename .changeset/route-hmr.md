Route HMR (development only) runs on a new runtime that the router plugin's dev output imports from new `/hmr` subpaths (`@tanstack/router-core/hmr`, `@tanstack/{react,solid,vue}-router/hmr`). It updates the live route in place and keeps each split component's lazy wrapper across updates. Nothing of it reaches production bundles, and production and server code never load it.

- **React: an edit always shows.** The router takes the new component once React Refresh ran its refresh pass (or after 200 ms when no pass comes), and React Refresh alone decides whether the component keeps its state. An update that gives the route no component React Refresh may patch (each one split, as `autoCodeSplitting` does by default, absent or unchanged) applies as soon as the module evaluates. A component React Refresh can't patch (`const Page = flag ? Wide : Narrow`, a factory's result, an unexported class, a layout import switched to another module) kept showing the old code until a reload.
- **Solid: an edit always shows.** The router keeps the component it holds only when solid-refresh patched it in place (both are solid-refresh proxies of the same component name and file). Before, a component chosen by a condition (`flag ? Wide : Narrow`), a swap through a barrel or a rename in an unsplit route could stay stale. Split chunks carry the route file's `@refresh` comments (`// @refresh granular`, a copy of the comment alone, read where the refresh plugin reads it in the file; the statement it is on still runs once), so a split component keeps its state where an unsplit one does; on React, a split component resets on every edit under `/* @refresh reset */` as an unsplit one does. After a rename or a removed component in a split route, later edits show only after a reload (solidjs/solid-refresh#88). A `codeSplitGroupings` edit that moves a component to another chunk (or in or out of the split), or removes a component from a chunk another component stays in, reloads the page; before, the edits after it stayed stale until a reload. Adding or removing another component (an `errorComponent`) updates in place. Restoring a deleted file a split component reads reloads the page once, on every host, also with Rsbuild's `dev.liveReload: false` (solid-refresh patches a module only in its own update on Vite); before, the page showed the old file until the next edit on Vite.
- Lazy route files (`createLazyFileRoute`, `*.lazy.tsx`) update in place instead of reloading the page, on Vite and Rsbuild, for React, Solid and Vue; a React component keeps its state when React Refresh can patch it. The page still reloads when the edit removes an option the route had loaded from the lazy file (the route file's value shows again).
- On Rspack, an edit of a split loader refreshes the route; the page kept the old loader's data.
- An edit of a Vue route file keeps the component of its `*.component.vue` file; the page went blank until a reload.
- An update reaches every router of the page that holds a route the edited file evaluated to (or that loaded its lazy route file's options), whichever router was created last: two routers of one route tree (React StrictMode's state initializer) both show it. Another router's route of the same id from another file (a widget's code router, a second route tree compiled by its own plugin instance, module federation) is left alone (#7921). Before, an edit could reach only the router created last, or the other router's route.
- One save that changes a loader's data shape and the component reading it shows in place, React, Solid and Vue; before, the page could end on the error screen until the next save. In a Start app whose root route renders the document and has no route `errorComponent` (or router `defaultErrorComponent`), React reloads the page once in that save; Solid and Vue can leave the page blank or on the error until the next route save, which reloads.
- After a render error, the edit that fixes it shows in place in a client-only app and wherever a route error component caught it (in a Solid Start app whose root route renders the document in its component, the root's own error component replaces the document, and the fixing edit reloads the page); before, a route edit after any caught render error reloaded the page, also after the page had recovered.
