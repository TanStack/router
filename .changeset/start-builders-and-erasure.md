'@tanstack/start-plugin-core': minor
'@tanstack/start-client-core': patch

Start never ships server code to the client through a builder it can't follow: each use of a Start builder or factory (`createServerFn`, `createMiddleware`, `createIsomorphicFn`, `createServerOnlyFn`, `createClientOnlyFn`, `createStart` and what they return) is either compiled or fails the client build at that use, with the fix. In development the module fails (the overlay shows it).

- **Now compiled** (their handlers shipped to the client): a factory destructured from a Start namespace (`const { createServerFn } = Start`), `(0, createServerFn)()`, a builder chosen by `?:`, `??`, `||` or `&&` between two builders of the same kind, a factory with statements before its single `return`, a project namespace re-exported (`export * as ns`) and read by member, a factory that two `export *` branches reach under two names of one binding (`export { api as a, api as b }`, or an imported binding exported beside a re-export of it), and a factory exported as `'*'`.
- **Now a client build error, at the use:** a builder or factory passed to a function, stored in an object, an array or a class field, awaited or rendered as a JSX prop; a method read off a builder (`const h = createServerFn().handler`, `.call`, `.bind`) or an unknown method; a builder returned from a function with control flow, from an async function, a method or a getter; a `let` builder reassigned with anything else; a builder destructured; a builder in a TS `namespace`; a project namespace object passed around when its module exports a builder; a choice between two isomorphic functions of which only one's call returns a builder; a server function built on a `var` that redeclares a function or a parameter.
- **A client-only `createIsomorphicFn().client(fn)` or `createMiddleware().client(fn)` passed to other code** fails the client build too, as a precaution: pass the middleware to `.middleware([…])` or `createStart`'s lists directly, or end its chain with `.server(({ next }) => next())`; give the isomorphic function `.server(() => undefined)`, or use `createClientOnlyFn(fn)`.
- **A function parameter that reaches server code:** passed directly as the server code (`(fn) => createServerOnlyFn(fn)`, `({ handler }) => createMiddleware().server(handler)`), it fails the client build, since every call keeps its argument on the client. Only read inside the server code (`(role) => createMiddleware().server(() => check(role))`), it gets one warning at its definition: what callers pass for it ships to the client, so don't pass secrets or server code through it.
- **Builder options:** passing a builder's options object on, writing to it or reading its `middleware` list fails the client build; read the options you need by name (`base.options.method`, `const { method } = base.options`). A builder's `.options` is typed read-only.
- **`.inputValidator()`** (renamed to `.validator()` in #7566 and removed in #8694) fails the client build at the call, saying to call `.validator()` or to update the dependency that calls it.
- **Not followed, no error:** `import()`, `require()` and `import.meta.glob` of Start objects, and modules other plugins generate or rewrite. Keep builders statically analyzable.
- **Called at once with a method:** an env-only or isomorphic function whose implementation is a method and that is called where it is created (`createClientOnlyFn(obj.method)()`, `createIsomorphicFn().client(obj.method)()`) calls the method detached (`(0, obj.method)()`), as the function the factory returns does. It was called with `obj` as `this`.
- **Erasure:** a class, `enum` or `namespace` that only code removed for the other environment uses (a handler on the client, an isomorphic function's `.server()`, a `createServerOnlyFn` body) is removed with the imports only it uses; it stayed in the client bundle with its imports.
- **TypeScript from another Vite plugin:** a file that is no JavaScript, which a plugin hands to the bundler as TypeScript (`moduleType: 'ts'` or `'tsx'`), is compiled as TypeScript; its handlers shipped to the client.

**Vue single-file components:** the script blocks are compiled on Vite and on Rsbuild with `@rsbuild/plugin-vue`. On Rsbuild, an SFC that imports Start failed the build. On the dev servers and in builds with Vue's devtools (Vite: `features.prodDevtools`, a true `__VUE_PROD_DEVTOOLS__` define or `NODE_ENV=development`; Rsbuild: `NODE_ENV=development`), Vue hands a `<script setup>` block's bindings to its template, in JavaScript every import too: a JavaScript block that imports a builder or factory, or a block whose local holds an open builder, is an error at that binding. No server code ships. Two of these shapes built before: a JavaScript block importing a builder it never uses, and one importing the namespace of a module that exports a builder. A default production build inlines the template and builds, except on Vite for an SFC with `<template src>`, which `@vitejs/plugin-vue` doesn't inline. Use `<script setup lang="ts">`, define builders, factories and middleware in a `.ts` module, and import them or the finished server functions.
