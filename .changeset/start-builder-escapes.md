Start never ships server code to the client through a builder it cannot follow: each use of a Start builder or factory (`createServerFn`, `createMiddleware`, `createIsomorphicFn`, `createServerOnlyFn`, `createStart` and what they return) is either compiled or fails the client build with an error at that use.

- **Newly compiled:** a Start namespace or start instance destructured (`const { createServerFn } = Start`, `const { createMiddleware } = createStart(…)`), `(0, createServerFn)()`, a builder chosen by `?:`, `??`, `||` or `&&` between two builders of the same kind, a factory with statements before its single `return`, a project namespace re-exported (`export * as ns`, `export { ns }`, `export default ns`) and read by member, a `let` builder reassigned with a builder of the same kind, a `const` list of middleware passed to `.middleware(list)`, `createServerFn.call(thisArg, options)`, a method called on a finished server fn, a builder merged with a type of the same name, and the JavaScript of `.mdx`, `.vue`, `.svelte`, `.astro` and `.marko` modules (their server functions are compiled in place; exporting an open builder from one is an error).
- **Now a client build error, at the use:** a builder or factory passed to a function, stored in an object, an array, a class field or another variable, awaited or rendered as a JSX prop; a method read off a builder (`const h = createServerFn().handler`, `.call`, `.bind`); a builder returned from a function with control flow, from an async function, a method or a getter; a `let` holding a builder reassigned with anything else; a builder destructured; a project namespace object passed around, when its module exports a builder; a builder in a TS `namespace`; a client-only `createIsomorphicFn().client(fn)` or `createMiddleware().client(fn)` passed to other code (use `createClientOnlyFn(fn)`); `renderServerComponent` or `createCompositeComponent` outside a server function; a route factory call other than the one bound to `Route` carrying `server`, `ssr` or `headers`.
- **A function parameter that reaches server code:** passed directly as the server code (`(fn) => createServerOnlyFn(fn)`, `({ handler }) => createMiddleware().server(handler)`, an isomorphic `.server(fn)`, `.validator(schema)`), it is a client build error at that use, since its argument is server code and every call keeps it on the client. Only read inside the server code (`(role) => createMiddleware().server(() => check(role))`), it gets one warning at its definition: the arguments of its calls still ship to the client, so do not pass secrets or server code through it.
- **Also fixed:** any import of a `server-only` or `client-only` marker marks the module, as does a top-level `import()` of it; a re-export cycle through `export *` resolves; on Rsbuild the compiler resolves imports with their `exports` conditions; a `name:` specifier behind an alias or a plugin is read.
- **Route options the compiler can't read build and warn:** a spread, options from a call or an import, and a computed key. What they hold isn't split or removed, so any server code in them ships to the client; the warning says what to write instead. A `server`, `ssr` or `headers` written next to a spread is still removed.
- **Not followed, no error:** `import()`, `require()` and `import.meta.glob` of Start objects, and modules other plugins generate or rewrite. Keep Start's builders statically analyzable.

In development the same errors fail the module (the overlay shows them).
