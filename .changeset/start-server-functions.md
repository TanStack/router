Server functions:

- **Written in any position evaluated once at load.** A server function that isn't a top-level declaration builds when its expression runs exactly once, unconditionally, when the module loads: an object or array entry, a call argument, `export default`, an assignment, a member's object (`.bind(null)`), a class's static field or block, a top-level `await`. It is created at its place in the module's order. These failed Vite builds (`createServerFn must be assigned to a variable!`) and, on Rsbuild, shipped their handler to the client and registered nothing. Other positions fail the build (see the unsupported shapes changeset).
- **One instance per server function** (SSR as the provider): a handler shares its module's state and classes with the rest of the module, so `instanceof` holds and the state the module writes is what the handler reads (#8656). Server code that imports a server function calls it directly (#7213, #8731), also one no client module imports, which failed with `Server function info not found`. A handler, its validator and what only they use still load on the first call; a handler that reads or writes its module's state at load, or one in a module with top-level `await`, loads with its module.
- **Recognised by binding** through re-exports, namespaces, aliases, the app's factories and stored builders, whatever the formatting (#7280). `createServerOnlyFn(…)` passed to `.handler()` works (#8446). A handler that is itself a `createClientOnlyFn(…)` throws when called (`… can only be called on the client`); the client implementation ran on the server.
- **HTTP calls:** as before, production answers HTTP calls only for server functions some client module references. The dev server still answers the others, and now warns once per function that a production build refuses the call.
- **Ids** keep their formats: the default id, the `functionName` a custom `serverFns.generateFunctionId` receives, `serverFnMeta.name` and the manifest's quoting, so custom ids stay the same. On Vite, ids a custom `generateFunctionId` makes collide across files get their `_1`, `_2` suffixes in file path order, so such ids can change once. A server function that isn't declared as a variable takes the name it is assigned to (an object property, a class field), `default` for `export default`, and `fn` otherwise.
- **Kits that list Start under `dependencies`** (instead of `peerDependencies`) are bundled on the Vite server and compiled, like peer-dependent kits; their server functions returned `undefined` during SSR. Like peer kits, they're now excluded from Vite's dependency optimizer, so `vite dev` serves them unbundled: if such a kit or its dependencies are CommonJS, add them to `optimizeDeps.include` (`'kit > dependency'` for a nested one). A library the app doesn't list in its `package.json` isn't bundled this way: on Vite its server functions throw during SSR (HTTP 500), so declare it.
- **`vite build --watch`:** the server builds once the client's first build is done, so the first build answers server function calls (none answered before); a server function the client stops importing is no longer callable after the rebuild; and a rebuilt server's documents load the client's latest build. The two watchers coordinate through a file in a per-run directory under the system's temporary directory: a `build.watch.exclude` matching that directory isn't supported, and a temporary directory that can't be used leaves the build working, with a warning that says to fix it or set `TMPDIR`.
- **Vite dev:** a request for a server function the dev server hasn't compiled yet (a page left open across a restart) compiles the file its id names when that file, with symlinks resolved, is inside the app's `srcDirectory`, outside `node_modules` and allowed by `server.fs` (#8447). Any other id the dev server hasn't registered is refused with `Invalid server function ID`, as before. A server function an edit removes answers `Invalid server function ID` instead of a 500 `TypeError`.
- **Rsbuild:** server-only routes are pruned from the client route tree (#8545). A server function that only a worker built in a child compiler (`worker-rspack-loader`, workbox) calls is registered.
- **RSC:** server functions that only a `'use client'` component imports are in the production manifest (#7943). `renderServerComponent` or `createCompositeComponent` outside a server function fails the build at the call; it built and threw at runtime (`… cannot be called on the client`).
