Route code splitting places top-level code by the bindings it reads and writes only, as before the compiler rewrite: a declaration only split code reads moves into that code's chunk whatever is written before or after it (`const Schema = z.object(…)` read by the component now moves past a `validateSearch` schema the route module keeps). What moves keeps its source order in its chunk, what stays its order in the route module. A statement that declares nothing (a call, an assignment, an `if` block) moves with what it touches: into a chunk when every module binding it touches (and every object those hold) goes to that chunk (`const table = createTable(); const columns = snapshot(table); table.addColumn('x')`, only the page reading `columns`, all move, in that order); it stays in the route module when it touches an import (`Sentry.init({ dsn })`, `i18n.use(backend)`) or a binding the route module or another chunk keeps. A statement changing something the compiler cannot see (`registry.install()` patching `fetch`, with `registry` only read by the page) then runs when the page's chunk loads. Code that depends on another top-level call having run first without reading its result (`const app = initializeApp(config)` read only by the page, before `const auth = getAuth()` kept by the loader, or before a bare `hydrateStores()`) then runs in another order: pass the dependency (`getAuth(app)`) or move both to their own module.
