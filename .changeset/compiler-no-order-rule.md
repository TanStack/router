Route code splitting places top-level code by the bindings it reads and writes only, as before the compiler rewrite: a declaration only split code reads moves into that code's chunk whatever is written before or after it (`const Schema = z.object(…)` read by the component now moves past a `validateSearch` schema the route module keeps). What moves keeps its source order in its chunk, what stays its order in the route module. A statement that declares nothing (a call, an assignment, an `if` block) moves with the bindings of the module it uses (reads or changes, also in the local functions it calls): into a chunk when they all go to that chunk (`const table = createTable(); const columns = snapshot(table); table.addColumn('x')`, only the page reading `columns`, all move, in that order; `plugins.push(sentryPlugin())`, `Sentry.init(cfg)`, `window.x = cfg`, `console.log(cfg)` move with `plugins` or `cfg`). Otherwise it stays in the route module, with what it uses: when a binding it uses is needed by the route module, exported, or used by another split option, or when it uses none that moves (`Sentry.init({ dsn })`, `i18n.use(backend)`); the `eager-split:written` warning names that binding and the statement's line. A callback registered at load moves with what it writes, and on the server, startup work used only by a server function starts with its first call. Code the compiler cannot see into (`registry.install()` patching `fetch`, with `registry` only read by the page) then runs when the page's chunk loads. Code that depends on another top-level call having run first without reading its result (`const app = initializeApp(config)` read only by the page, before `const auth = getAuth()` kept by the loader) then runs in another order: pass the dependency (`getAuth(app)`) or move both to their own module. A declaration nothing reads is never removed: it moves with what it reads (an unused `function Unused() { return <Page /> }` with `Page`) and the bundler decides; reading bindings of two outputs it stays, and a warning names it and what it keeps in the route module (delete it).
