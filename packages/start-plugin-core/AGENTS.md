# Start compiler and bundler integration

- Virtual prefixes and query parameters can be part of a module's identity. Preserve them in resolution, loading, and module-cache keys; use `cleanId` only for physical-file matching, diagnostics, and file invalidation. Load compiler dependencies through the bundler host.
- The compiler is a set of planners (`src/planners/`) on the shared [compiler core](../router-utils/src/compiler/README.md), hosted by one bundler-free session (`src/compiler/session.ts`: planners, configuration, registry, import protection, reporting) that `src/vite/compiler-plugin.ts` and the Rsbuild loaders ([COMPILER_ARCHITECTURE.md](src/rsbuild/COMPILER_ARCHITECTURE.md)) wire to their bundler. Server-function recognition is in `src/compiler/`, ids/registry/resolver in `src/server-fns/`.
- For import-protection changes, read `src/planners/edges.ts` (per-output edges, mock substitution) and `src/import-protection/` (rules, build verdicts after tree-shaking, `onViolation` fixed point, reports). Preserve adapter-specific deferral and survival checks; development has no build-time tree-shaking, and Vite's error/mock modes differ. Cover actual leaks and safe boundaries in cold/warm development and builds.
- Compiler output must match runtime contracts in `start-client-core`, `start-fn-stubs`, and `start-server-core`. For `createServerFn`, cover client, SSR caller, and server-provider output separately in [`tests/createServerFn/createServerFn.test.ts`](tests/createServerFn/createServerFn.test.ts).
- Use a built Start e2e app to validate generated imports and runtime behavior together; compiler snapshots alone do not exercise that integration.
- The shared compiler serves both Vite and Rsbuild. For shared compiler changes, check the relevant adapter suites in `tests/integration/rsbuild/` and the Vite and Rsbuild rows of the compiler tests, plus affected Start e2e modes for build, server-function, or HMR behavior.
- Tests run in two tiers. `test:unit` (fast tier, the inner loop) runs `tests/**` in process and depends on `^build` only. `test:integration` (slow tier) runs `tests/integration/**`: every test that starts a real build (`buildStart`), a dev server that links the built `@tanstack/react-start` (`startDevServer`, `startProtectedDevServer`, `linkStartRuntime`), an Rsbuild dev server, a child Node process or a browser page; its Nx target builds `@tanstack/react-start` first. Put such tests under `tests/integration/`; a file with tests of both kinds is split by test into files of the same name in both directories. Run both tiers before handing back.
- To run one test file or `-t` filter quickly, the slow-tier load gate and the test budgets: [compiler-test-utils/AGENTS.md](../compiler-test-utils/AGENTS.md).
- What these tests are, the spec they cite (`J4.12`, `G3`, `§5.7`) and the known bugs: [compiler-test-utils/oracle/README.md](../compiler-test-utils/oracle/README.md).
- `test:noncompiler` runs main's tests of features that are not compilers (manifest, sitemap, prerender, schema, entries, build output, dev styles), at main's paths and unchanged from main, listed in `tests/noncompiler-tests.json`; the compiler test projects and ESLint leave them out. Root PR/CI and the compiler platform jobs run it. Run it before handing back.
