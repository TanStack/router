# Router bundler plugin

- Code splitting must not change what a route does. The route module and its split chunks share one instance of every module-level value: `Route` and any state created at module load exist once, and every chunk sees the same object. The one exception by rule (R77, [ARCHITECTURE-CODE-SPLITTING.md](ARCHITECTURE-CODE-SPLITTING.md)): a pure, unassigned exported binding only chunks need is copied into each chunk, and other importers of the route file share one instance of it; state, effects and augmented bindings are never copied. Which other bindings the splitter shares, copies or leaves in the entry is an implementation choice; tests assert values, identity and init counts, never placement.
- Every option configured for splitting must end up split. When a pattern the user can change prevents it, the option keeps working in the entry and the build warns once, naming the file. When the limitation is ours, it is a bug to fix, not a warning.
- Splitting and route HMR are planners on the shared compiler core: read [ARCHITECTURE-CODE-SPLITTING.md](ARCHITECTURE-CODE-SPLITTING.md) and the [core README](../router-utils/src/compiler/README.md). Planners only declare roots and edits; placement, dead-code removal and emission belong to the core.
- Generated route HMR code stays minimal: it calls the framework's `__tsrRouteHmr` from the dev-only `/hmr` subpath (`router-core/src/hmr.ts`), which updates the live route in place (only the route its module exported), replaces lazy-chunk ownership, rebuilds the route tree and refreshes active matches while preserving component identities (React, Solid and Vue). Keep that bookkeeping in the runtime, not in emitted code, and keep it out of production bundles.
- Tests run in two tiers. `test:unit` (fast tier, the inner loop) runs `tests/**` in process; a Vite dev server in middleware mode is allowed. `test:integration` (slow tier) runs `tests/integration/**`: every test that starts a real build (`build`, `buildAndRun`), an Rsbuild dev server or watch compiler, a child Node process or a browser page (`openRouteHmrPage`). Put such tests under `tests/integration/`; a file with tests of both kinds is split by test into files of the same name in both directories. Run both tiers before handing back.
- Test code-splitting changes by behaviour: load the route with `loadRoute` from `tests/route-app.ts` (a real Vite dev server with the public plugins; the route runs in a real browser page), and assert what users see (rendered output, loader results, init counts). Outcomes the bundler decides (dead code, chunk contents, `sideEffects` / `@__PURE__` hints) are asserted in a real build with `build` from `tests/build-harness.ts`, per bundler. Do not add output snapshots.
- Run behavioural tests for React, Solid and Vue through the `targetFramework` option of the test helpers.
- Test what the page shows after a route file edit with `openRouteHmrPage` (`tests/route-hmr-page.ts`): a real dev server with the framework's plugin, a real browser page and the real HMR client. Never copy bundler, HMR-client or React Refresh logic into tests. There is no in-process HMR model: test route HMR with `openRouteHmrPage`.
- To run one test file or `-t` filter quickly, the slow-tier load gate and the test budgets: [compiler-test-utils/AGENTS.md](../compiler-test-utils/AGENTS.md).
- What these tests are, the spec they cite (`J4.12`, `G3`, `§5.7`) and the known bugs: [compiler-test-utils/oracle/README.md](../compiler-test-utils/oracle/README.md).
