# Router bundler plugin

- Preserve one initialization of shared module state across reference and split chunks. Shared extraction includes transitive dependencies and whole destructured declarations; never extract `Route` or bindings that depend on it.
- `handleRouteUpdate` is stringified and injected into app modules. Keep runtime dependencies inside the function or explicitly emit them; extracting a helper to plugin module scope breaks the generated function. `tests/handle-route-update.test.ts` executes that emitted code.
- Route HMR rebuilds indexes, clears `resolvePathCache`, replaces lazy-chunk ownership, and refreshes active routes while preserving Fast Refresh component identities. Keep these steps coordinated when adding derived state.
- Tests run in two tiers. `test:unit` (fast tier, the inner loop) runs `tests/**` in process; a Vite dev server in middleware mode is allowed, and client checks run in pages of a headless Chromium (`pnpm exec playwright install chromium`). `test:integration` (slow tier) runs `tests/integration/**`: every test that starts a real build (`build`, `buildAndRun`), an Rsbuild dev server or watch compiler, a child Node process or a browser page. Put such tests under `tests/integration/`; a file with tests of both kinds is split by test into files of the same name in both directories. Run both tiers before handing back.
- Test code-splitting changes by behaviour: load the route with `loadRoute` from `tests/route-app.ts` (a real Vite dev server with the public plugins; the route runs in a real browser page), and assert what users see (rendered output, loader results, init counts). Outcomes the bundler decides (dead code, chunk contents, `sideEffects` / `@__PURE__` hints) are asserted in a real build with `build` from `tests/build-harness.ts`, per bundler. Do not add output snapshots.
- Run behavioural tests for React, Solid and Vue through the `targetFramework` option of the test helpers.
- The `unit-main` project (`vite.config.ts`) holds tests of the Babel-based compiler's output and internals that the tests above do not replace yet: route HMR (`add-hmr`, `handle-route-update`, `react-refresh-route-components`, `router-plugin-context`), the remaining code-splitter snapshots and `production-warnings`. Keep them passing; add new tests to the tiers above, not to them.
- To run one test file or `-t` filter quickly, the slow-tier load gate and the test budgets: [compiler-test-utils/AGENTS.md](../compiler-test-utils/AGENTS.md).
- What these tests are and the spec they cite (`J2.5`, `G3`, `§5.7`): [compiler-test-utils/oracle/README.md](../compiler-test-utils/oracle/README.md).
